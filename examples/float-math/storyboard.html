Why does 0.1 + 0.2 not equal 0.3?Why doesn't zero point one plus zero point two equal zero point three?

PromiseComputers store numbers in binary, and 0.1 has no exact binary form (as 1/3 has no exact decimal form), so the stored values are a tiny bit off and the error shows when you add them; so compare floats with a tolerance, and use integers or decimals for money.
AudienceDevelopers and curious students watching a short on a phone. They have seen 0.30000000000000004 or will; they know what binary is, roughly, but not why a short decimal can be inexact in it.

f1In IEEE 754 double precision (the number type of JavaScript, and Python's float), 0.1 + 0.2 prints 0.30000000000000004 and 0.1 + 0.2 == 0.3 is false. Run here: Python 3 repr(0.1 + 0.2) -> '0.30000000000000004'; Node: 0.1 + 0.2 -> 0.30000000000000004, 0.1 + 0.2 === 0.3 -> false. That string has fifteen zeros between the 3 and the 4.Run in this workspace (Python 3, Node). Python tutorial, 'Floating-Point Arithmetic: Issues and Limitations' (docs.python.org/3/tutorial/floatingpoint.html, read via a search summary); IEEE 754-2019.
f2A binary fraction is a sum of halves, quarters, eighths...: 0.75 = 1/2 + 1/4 = 0.11 in binary, exactly. A fraction ends in binary only if its denominator (in lowest terms) is a power of two; 1/10 has a factor 5, so it never ends.Arithmetic; Python tutorial, Representation Error section.
f30.1 in binary = 0.0001100110011001100110011... (the group 0011 repeats forever after 0.0); 0.2 = 0.001100110011... (computed bit by bit with Python's fractions module). 1/3 in decimal = 0.333... for the same reason: 3 does not divide a power of ten.Computed here with fractions.Fraction(1, 10), doubling and taking the integer part 64 times.
f4A double has 53 bits of precision (sys.float_info.mant_dig = 53). 0.1's 53 bits from its first 1: 11001100110011001100110011001100110011001100110011001 followed by 1001100..., so it is rounded to the nearest, up: 11001100110011001100110011001100110011001100110011010 (0.1.hex() = 0x1.999999999999ap-4).Run here: sys.float_info.mant_dig, float.hex, Fraction(0.1). IEEE 754-2019 binary64 (52 stored fraction bits plus the hidden leading 1).
f5The double nearest 0.1 is exactly 0.1000000000000000055511151231257827021181583404541015625 (decimal.Decimal(0.1)), 5.55e-18 above 0.1. The gap between neighbouring doubles there is 2^-56 = 1.39e-17, so the stored value is 0.4 of a gap above 0.1 and 0.1 is 0.6 of a gap above the double below. Drawn at 560 px a gap. The zoom from the 0-to-0.4 line (866 px for 0.4, 4.6e-4 per px) to that one (2.48e-20 per px) is about 1.9 x 10^16, shown as 'zoom ×10¹⁶'.Run here: decimal.Decimal(0.1), math.ulp(0.1), fractions.
f60.2 is stored 1.11e-17 too big, 0.1 5.55e-18 too big. Near 0.3 the gap between doubles is 2^-54 = 5.55e-17. The double nearest 0.3 is 0.299999999999999988897769753748434595763683319091796875, 0.2 of a gap below 0.3. The exact sum of the two stored values is 0.3000000000000000166533453693773481063544750213623046875: 0.3 plus 0.1 + 0.2 = 0.3 of a gap, which is exactly halfway between that double and the next; round-half-to-even picks the next, 0.3000000000000000444089209850062616169452667236328125, the shortest decimal that names it being 0.30000000000000004. Drawn at 600 px a gap: 0.3's double at x 200, 0.3 at 320, the errors 60 and 120 px, the exact sum at 500, the answer at 800. The film shows the hop as 'rounded' and does not explain ties. That line is zoomed (600 / 2^-54) / (866 / 0.4) = 4.99 x 10^15 times, shown as 'zoom ×10¹⁵ near 0.3' (less than at 0.1, because the gaps are four times wider there).Run here: fractions.Fraction(0.1) + Fraction(0.2) compared with Fraction(0.3) and Fraction(0.1 + 0.2); math.ulp(0.3).
f7The usual fixes: compare with a tolerance (Math.abs(0.1 + 0.2 - 0.3) < 1e-9 is true; Python has math.isclose(0.1 + 0.2, 0.3) -> True), and for money use whole cents as integers (10 + 20 === 30) or a decimal type (Python Decimal('0.1') + Decimal('0.2') == Decimal('0.3') is True). 1e-9 is an example tolerance; the right one depends on the size of the numbers.Run here (Node and Python). Python tutorial recommends the decimal module for accounting.
